# Guarded private production executor

`runProductionPrivateAcceptance` is an operator-only library entry. It accepts an explicit one-run grant for an exact workflow run/head, a 600-second lease, the reviewed baseline, and external attestations that the production execution qualification, fresh independent preflight on the same approved head with a distinct preflight run ID and explicit verification attestation, custodian and operator are ready. CI, a fixture pass or an environment flag never creates this grant. The function has no automatic invocation, CLI, HTTP route, credential-minting path or workflow dispatch capability.

The adapter checks the five reviewed consumer hashes and an unused owner-only output path before acquiring a durable exclusive run claim. It watches the exact authenticated Actions run, attempt, named steps and artifact digest, requiring fresh proof and at least 180 seconds of remaining lease. It then copies only the five pinned consumer modules plus the pinned package initializer into a private snapshot, verifies and executes the same canonical interpreter path (never the original symlink), explicitly resolves the qualified venv dependency directory, and starts the actual consumer CLI through a hash-pinned supervision bootstrap in one owned Terminal window. The window is created inert, tagged with an ephemeral unique title and identified numerically before the CLI command is submitted; no localized Terminal reference or front-window lookup is used. Python isolated mode excludes user/environment import paths. The consumer independently repeats authenticated receipt and live DID/Card/health checks before private input and retains its own checks around input, login, token retrieval and both intended requests.

The bootstrap does not read, store, log or alter input. It observes the real getpass terminal mode change and emits a sanitized ready marker only after echo is disabled. The operator types directly into Terminal. A callback can notify the rollout owner without pausing the timed path. Readiness markers carry no prompt, input, token or response data. There is no password argument or environment file.

The adapter stops on signal, ambiguity, proof expiry, a 60-second unlock timeout or loss of lease headroom. The supervisor first establishes its own foreground process group in that owned TTY. SIGTERM raises an exception in the Python supervisor, allowing getpass to restore echo; escalation is confined to the owned process/group. Only the returned exact Terminal window is closed. The adapter rechecks abort, proof age and lease floor again at completion, then verifies the fixed sanitized acceptance receipt, owned process exit and window closure, and removes its snapshot/markers. Missing process identity, a non-owned group or uncertain process/window exit can never be reported as verified cleanup. The caller's designated sanitized output receipt remains available as evidence. It never cancels the workflow: mandatory Cloudflare OFF/lease/binding cleanup and custodian token revocation remain independently owned requirements, including on any launch failure. No automatic replay or retry is performed.

## Local qualification and limits

`qualifySyntheticPrivateExecutor` creates a fixed hash-pinned synthetic CLI and uses the same observer, snapshot, process, Terminal and cleanup implementation with OS networking denied. The pinned synthetic CLI must observe OS permission denial on a native loopback connection before it can reach private input. The synthetic CLI uses real getpass and writes only the fixed sanitized acceptance result; it has no authentication or HTTP transport. Explicit tests cover successful hidden input, no-input timeout, stop at the prompt, echo restoration, duplicate refusal, receipt permissions and exact window/process cleanup. Other tests cover every production grant prerequisite and proof-age/lease bounds. The existing consumer tests independently cover the actual authentication, signed Card and request/retry semantics using MockTransport; the separate unmodified CLI negative qualification exercised its real module entrypoint and Actions API plumbing with networking denied.

Run ordinary tests with `npm --prefix tools/agent-contact-pilot test`. Explicit native cases require `EXP710_PRODUCTION_EXECUTOR_FIXTURE=1` and `EXP710_REHEARSAL_PYTHON` naming the qualified isolated Python environment. Generic CI skips the native cases. No production function is called by these tests, and no live services, credentials, workflow dispatch or deployment are used. Synthetic source success is not a successful hosted acceptance result.
