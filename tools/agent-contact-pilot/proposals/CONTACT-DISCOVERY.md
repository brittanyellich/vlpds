# Fixed-pilot contact discovery contract

This local, network-free slice validates the existing experimental `link.ident.agent/self` pointer. It does not publish a record, mount a route, fetch a URL, index an agent or admit a caller. It is deliberately limited to the existing fixed pilot agent/principal and signed Card template; a second agent and a general directory remain follow-up work.

The resolver must independently obtain fresh trusted DID documents and repository heads before/after bounded reads. `agent_discovery::discover_fixed` then composes the existing native ident.link endorsement verifier, signed agent-repository inclusion/absence proof, independent record read and existing Card signature/origin checks. Its public result contains only the fixed DID-scoped HTTPS Card and JSON-RPC endpoint plus proof CIDs. No caller, credential, private profile or Space reference is accepted or returned.

The proposed opt-in record has exactly `$type: link.ident.agent` and `agentCardUrl`, at the fixed agent's `self` key. The URL must equal its current PDS origin plus the existing stable per-agent Card path. Arbitrary override URLs, unknown fields, contact-record/CAR mismatch, changed heads, missing or unavailable evidence, invalid signatures and changed Card authority fail closed. Signed contact or endorsement removal stops discovery. This is a local contract qualification, not a claim that this draft NSID has been published or its DNS authority delegated.

Discovery provides routing evidence only. Native dispatch still requires its independent caller service JWT, allowlist, owner consent, current endorsement, disable/revocation policy and idempotency checks before cached reply or bridge execution. Do not use a `Contact` value as an authorization grant or stale fallback. The existing Card server is unchanged; hosted fetch/mount and routing integration must be separately qualified with disposable fixtures before staging.

Next integration: test Card/record publication and removal using disposable repositories, add a second agent, then connect the resolved DID endpoint to the existing scoped admission path. Keep public metadata and private consent separate. No production enablement, live identity changes or new credential operation is included.

## Bounded resolver follow-up

`agent_discovery_fetch::observe_fixed` supplies the fixed pilot's trusted inputs through the existing guarded HTTPS proof transport. PLC and PDS origins, expected service audience, Card path, repository paths and both DIDs are fixed. It observes both repositories and rereads both DID documents around record/proof/Card acquisition, with the existing per-request bounds and a 20-second total deadline. It reports `Advertised`, `NotAdvertised` or `Unavailable`, with observation start time; this does not establish an authorization or global freshness lease. No cache, stale fallback, record-supplied fetch URL, HTTP route or runtime switch is introduced.

Synthetic byte responses use the existing compile-time-only transport seam and the same proof/Card verifier as production. Tests cover exact fixed requests, signed removals, changed heads/documents, invalid Card/URL, proof failure, status/media/encoding/size rejection, total timeout and observation age. Existing mounted fixture and admission tests remain necessary to qualify the unchanged independent caller/consent boundary. The resolver has not been invoked against live services. Hosted publication/staging, second-agent support and directory lookup remain subsequent milestones.


## Default-off normal-router mount

An embedding server may explicitly set `Config.agent_discovery = Some(agent_discovery_route::Mount::fixed())`. Both `Config::default()` and the normal binary leave it `None`; no CLI switch is added. Production mounting requires the reviewed fixed public HTTPS origin and service audience. Disposable development qualification may use an exact IPv4 loopback origin. The experimental `GET /xrpc/chat.atagents.agent.discover` accepts no query or body and returns only public routing metadata with proof CIDs and observation start time. It does not publish a lexicon or claim DNS authority for the draft method namespace.

When disabled, the reserved method returns unsupported rather than being proxied, including with an `atproto-proxy` header. Caller tokens and query fields cannot select a remote node for this method. When enabled, the public-only route uses the ordinary PDS HTTP/rate-limit layers outside request decompression, rejects encoded/framed requests before decoding, and has a one-second empty-body deadline and four shared in-flight resolver permits. Each resolver retains its 20-second bound. Queries and bodies are rejected before authority reads; there is no caller-selected DID or URL. Valid current evidence yields 200, signed removal 404, unavailable evidence or local saturation 503; handler responses are `no-store`.

The response never supplies a credential, consent decision, private profile or Space reference. Normal-router tests use synthetic byte/proof/Card inputs only and show that obtaining discovery metadata still leaves missing or forged caller authorization rejected by native contact before proof or bridge work. Per-agent disable, owner OFF and consent remain dispatch policy decisions and are not inferred from public discovery. No production mount, activation or live request was performed for qualification.
